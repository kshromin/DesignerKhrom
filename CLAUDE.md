# DesignerKhrom — конфигуратор корпусной мебели

Параметрический 3D-конфигуратор корпусной мебели (Three.js) — статический сайт, без сборки.
Открывать через `preview_start`, конфиг `static` в `.claude/launch.json`, **порт 8730**.

Второй продукт после конфигуратора шкафов-купе (папка `C:\CONFUG_NOUT`, репозиторий
`furniture-configurator`). Проекты **независимы**: свой репозиторий, свой сайт, свой вход.
Тот конфигуратор строит изделие из секций с наполнением, этот — **из отдельных панелей
с привязками**. Это разные модели данных, код не переиспользуется без разбора.

## С чего начинать работу

1. Прочитать **[ТЗ.md](ТЗ.md)** — что и почему делаем. Источник истины, составлен до кода.
2. Прочитать **[DEVLOG.md](DEVLOG.md)** — журнал сессий: что менялось и почему.
3. **[STRUCTURE.md](STRUCTURE.md)** — карта файлов. Держать в актуальном состоянии: любое изменение
   структуры (новый файл, разбивка модуля, смена ответственности) отражать сразу, в той же сессии.

## Где что лежит

- **Код** — эта папка, git-репозиторий, вне Яндекс.Диска. На GitHub: `kshromin/DesignerKhrom`.
- **`_work/`** — рабочая папка: черновики, выгрузки, всё временное. В `.gitignore`, на GitHub
  не уезжает, между машинами не ездит. Класть туда только то, что не жалко потерять.
- **Яндекс.Диск пока не используется** — работа идёт на одной машине. Подключим папку материалов,
  когда в работу войдёт второй компьютер.

## Рабочий процесс

- **Работаем по блокам**, по одной вещи за раз.
- **Коммитить** локально по завершении фичи, без вопросов — это дёшево и спасает историю.
- Экономить токены: не перечитывать большие файлы целиком, грепать точечно. STRUCTURE.md — карта,
  DEVLOG.md — контекст сессий, ТЗ.md — замысел.
- Каталог материалов конфигуратора шкафов-купе (`C:\CONFUG_NOUT\data\materials.json`) можно
  **изучать и копировать, но не править**. Общей базы пока нет — у этого проекта будет свой
  каталог, объединим позже.

### Команды «старт» и «финиш»

Сайт пока не опубликован, публикации на пуше нет — пушим свободно, ветку не разводим.

**«Старт»** — начало сессии:
1. `git pull` — подтянуть всё новое.
2. Прочитать ТЗ.md и DEVLOG.md.
3. Добавить запись «## <дата> — сессия N — НАЧАТА <время>», закоммитить, `git push`.

**«Финиш»** — конец сессии, без дополнительных вопросов:
1. Дописать тело записи в DEVLOG.md (что сделано и почему), сменить статус «НАЧАТА» на завершённую.
2. Закоммитить всё осмысленными коммитами.
3. `git push`.

Всё ценное должно попасть в репозиторий: код — коммитом, контекст — записью в DEVLOG. Что осталось
только в переписке чата, для следующей сессии не существует.
